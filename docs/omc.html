Executive Context

Why a Sovereign Git Platform is Essential for OMC

Addressing compliance, external vendor software risk, operational continuity, and intellectual property defense.

1. Regulatory Compliance & CERT-In Mandates
Government PSU regulations require critical digital assets, mining logistics code, and institutional data to remain within sovereign borders. Public SaaS repositories (e.g. GitHub/GitLab.com) expose OMC code to foreign cloud jurisdictions and external third-party outages.
2. Vendor Software Deliverable & Escrow Control
External system integrators, software contractors, and mining automation vendors often deliver software via zip files or vendor-owned accounts. ProGit gives OMC a unified internal escrow repository where vendors must commit source code directly for inspection.
3. Uninterrupted Intranet Operational Continuity
Mining sites and regional administrative offices require high availability. ProGit operates directly on OMC's internal WAN and LAN networks. Engineers, SCADA technicians, and IT teams can push, pull, and review code even during statewide Internet disruptions.
4. Unified Digital Mine IT Asset Portfolio
Centralize version control across ERP integrations, custom weighbridge automation scripts, drone survey spatial data parsers, mine telemetry pipelines, and employee portals under a single corporate governance umbrella.

Releases, Binary Artifacts & Vendor Software Escrow

Ensure cryptographic traceability of deployed software binaries and enforce code handover from external vendors.

Immutable Git Tag Releases
Publish formal version releases tied to cryptographic Git tags (e.g., v2.4.0-omc-prod). Ensure zero drift between source code and production binaries.
Binary Asset Attachments
Attach compiled executables, deployment containers, APKs, and firmware packages directly to release entries with automatic SHA-256 checksums.
Vendor Software Escrow
Eliminate vendor lock-in. Require third-party IT contractors to deposit complete source code, build manifests, and libraries into OMC's internal ProGit server.
Scoped Contractor Access
Grant external vendors access only to their contracted repositories. They cannot browse or clone unrelated OMC operational systems or internal tools.
The OMC Vendor Governance Advantage
By enforcing code delivery through ProGit pull requests, OMC's internal IT officers can run automated security scanning, inspect dependency trees, and review code before certifying contractor milestones.

Enterprise Identity, Access Control & Audit Compliance

Role-based permissions, centralized directory integration, and tamper-evident audit logging for CERT-In alignment.

Granular Role-Based Access Control (RBAC)

Enforce strict separation of duties across departments, mines, and administrative zones:

  • Organization & Team Hierarchies: Group repos by department (Mining IT, Finance & ERP, GIS & Survey, Admin).
  • Permission Levels: Owner, Admin, Write, Read, and Guest visibility controls.
  • Deploy Keys & Service Accounts: Read-only SSH keys for CI/CD runners and deployment servers.
Directory Integration & Security Auditing

Ready for enterprise directory authentication and regulatory compliance audits:

  • Active Directory & LDAP: Authenticate users against OMC's corporate Microsoft Active Directory / LDAP servers.
  • Immutable Security Logs: Comprehensive records of user logins, SSH access, branch pushes, and permission changes.
  • Personal Access Tokens (PATs): Fine-grained API and CLI tokens with individual expirations and revokability.
