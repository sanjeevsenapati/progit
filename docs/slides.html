Module 01 • Git Subsystem 02 / 20

Direct Bare Repository Architecture

How ProGit interacts directly with Git bare repositories on disk without heavy virtualization layers or CGO bindings.

Pure-Go Architecture Principles
Zero CGO Dependencies: Compiled with CGO_ENABLED=0 into a single standalone static binary. No dynamic libc dependencies, preventing binary segfaults.
Direct Bare Storage: Stores repositories as standard Git bare trees at /data/repositories/{owner}/{repo}.git with separate .wiki.git stores.
Process Group Sandboxing: Spawns Git CLI subprocesses inside isolated process groups (proc_unix.go), guaranteeing complete child process cleanup upon request timeout.
# On-Disk Bare Git Storage Layout
/data/repositories/
└── perfadmin/
│ └── microservice-auth.git/
│ │ └── HEAD           # ref: refs/heads/main
│ │ └── config         # bare = true, gc.autoDetach=false
│ │ └── objects/       # Loose SHA-1 & packfiles
│ │ └── refs/          # branches, tags, heads
│ │ ┌── hooks/         # internal pre/post hooks
│ ┌── microservice-auth.wiki.git/ # Dedicated wiki store
┌── enterprise-org/
    ┌── core-platform.git/

Module 01 • Git Protocols 03 / 20

Git Smart HTTP & Native SSH Daemon

High-speed wire protocol implementation supporting concurrent clone, fetch, and push over TLS and SSH.

1. Git Smart HTTP Protocol (Port 3000 / 3443)
Info Discovery: GET /owner/repo.git/info/refs?service=git-upload-pack streams framed packet-lines directly from the bare repository with zero buffering.
RPC Streaming: POST /owner/repo.git/git-upload-pack (clone/fetch) and git-receive-pack (push) pipe standard streams through authenticated HTTP Basic credentials or tokens.
Download Guard: Validates user permission; blocked immediately if repository or user has can_download = false.
2. Built-in SSH Daemon (Port 2222)
Pure-Go Daemon: Powered by golang.org/x/crypto/ssh. Does not touch host /etc/ssh, preventing port 22 conflicts and host key tampering.
Database Key Auth: Validates developer RSA, ECDSA, and Ed25519 public keys against SQLite/PostgreSQL with sub-millisecond lookup.
Execution Sandbox: Restricts commands to git-upload-pack, git-receive-pack, and git-upload-archive with strict path sanitization.
# Both protocols work out of the box with standard Git clients
git clone https://git.company.com/engineering/backend-service.git
git clone ssh://git@git.company.com:2222/engineering/backend-service.git

Module 02 • Installation 05 / 20

Zero-Friction Web Installation Wizard

Install, provision, and lock ProGit in under 60 seconds with an interactive web GUI or automated silent setup.

Setup Steps at /install
1. Instance Configuration: Define Application Name, Domain Hostname, Public Root URL, HTTP/HTTPS Ports, and Default Branch.
2. Super Admin Account: Create the root Super Administrator username, corporate email, and password.
3. Automatic DB Migration: Applies SQLite/PostgreSQL schema migrations and seeds system configuration tables.
4. Tamper-Proof Lock: Writes INSTALL_LOCK = true into app.ini and seals the installer permanently against replay attacks.
Headless & Container Auto-Provisioning
For CI/CD and automated Kubernetes GitOps rollouts, ProGit supports silent auto-installation through environment variables without opening the browser installer:
# Automated headless container deployment
ENV PROGIT_APP_NAME="Corporate Git"
ENV PROGIT_DOMAIN="git.internal.net"
ENV PROGIT_ROOT_URL="https://git.internal.net:3443/"
ENV PROGIT_HTTPS_PORT=3443
ENV PROGIT_SSH_PORT=2222
ENV PROGIT_INSTALL_LOCK=true
Security Guarantee: Strict Installation Lock
Once INSTALL_LOCK = true is set or any user exists, GET /api/v1/install/status reports locked and POST /api/v1/install unconditionally returns 403 Forbidden, preventing hostile admin takeover.

Module 04 • Operations & HA 11 / 20

SQLite WAL Mode & Database Maintenance

Concurrent read/write architecture, zero-locking transactional write-ahead logs, and online VACUUM defragmentation.

SQLite in Write-Ahead Logging (WAL) Mode
Non-Blocking Concurrency: Readers never block writers, and writers never block readers. HTTP reads execute concurrently at 20,000+ RPS without database lock contention.
Memory Synchronization: Changes write sequentially to progit.db-wal before checkpoints commit them back to the main database pages.
Dual-Engine Support: Open Source uses pure-Go SQLite; Enterprise Edition adds native PostgreSQL support for multi-node clusters.
Online Maintenance Operations
1. Checkpoint & Truncate WAL:
Executes PRAGMA wal_checkpoint(TRUNCATE) to flush pending write buffers and truncate the WAL journal to 0 bytes without locking.
2. Database VACUUM:
Executes SQLite VACUUM to rebuild the database file, defragment B-tree pages, and reclaim disk space from deleted users/repos.
# Trigger online WAL checkpoint via Admin Maintenance API
curl -X POST "https://git.company.com/api/v1/admin/maintenance" \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"operation": "checkpoint_wal"}'
Module 04 • Operations & DR 12 / 20

24/7 Operations, Backup & Disaster Recovery

Simple, foolproof disaster recovery: snapshot 3 directories, zero database corruption risks, and automated health checks.

Disaster Recovery Procedure
Step 1: Checkpoint DB: Trigger checkpoint_wal via API or cron to ensure zero unflushed WAL frames.
Step 2: Archive Volumes: Tar/snapshot the 3 persistent directories:
tar -czvf progit-backup.tar.gz /data/db /data/repositories /data/config
Step 3: Instant Restore: Untar to fresh host and start the container. ProGit boots in 1.2 seconds.
Production Health Probes
Liveness Probe (/api/health): Verifies SQLite DB ping, bare repository storage directory accessibility, uptime, and version. Returns 200 OK or 503.
Readiness Probe (/api/ready): Instant Kubernetes probe returning 200 OK once HTTP routers are bound.
Zero-Downtime Container Upgrades: Pull new tag (e.g. localhost/progit:1.7.0), stop old container, start new container pointing to same volumes.
