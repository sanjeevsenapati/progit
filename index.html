Getting Started / Overview & Philosophy

What is ProGit?

ProGit is an ultra-fast, single-binary, self-hosted Git collaboration platform engineered in pure Go with zero CGO dependencies and an embedded modern React frontend.

Core Mission & Philosophy

ProGit provides development teams and enterprises with an ultra-lightweight, resilient, and beautiful alternative to bloated Git platforms. It runs on any machine with less than 50 MB of RAM, boots in under 50 milliseconds, and operates without external database servers like PostgreSQL or MySQL.

Single Binary Simplicity
Everything — the HTTP REST engine, the Smart Git protocol handler, the built-in SSH server (port 2222), the SQLite WAL database engine, and the production React single-page frontend — is embedded into a single, compact, static binary.

Key Capabilities at a Glance

  • Pure Go & Zero CGO: Cross-compiles instantaneously to Linux, macOS, and Alpine containers without native GCC toolchains.
  • High-Concurrency SQLite WAL: Uses modernc.org/sqlite with Write-Ahead Logging (WAL) and automated checkpoint maintenance.
  • GitHub-Class Developer Experience: Complete with Pull Request line-by-line review comments, native Git merge engine, fork mechanics, and Kanban project boards.
  • Built-in ProGit Pages: Host static websites, documentation, and Jekyll/Markdown sites directly from your repository branches with zero setup.
  • Dual-Interface Wiki Engine: Edit documentation through the web interface or clone and push directly as a Git bare repository (<repo>.wiki.git).
  • In-Browser Code Editor & Prettier: Create files, edit code online, upload entire folder structures, and format with 8 built-in themes.

Getting Started / 5-Minute Quickstart

5-Minute Quickstart Guide

Get your own private ProGit instance running with Podman or Docker in less than five minutes.

Step 1: Launch Container

Run the following command in your terminal to start ProGit with persistent volumes:

podman run -d --name progit \
  -p 3000:3000 -p 3443:3443 -p 2222:2222 \
  -v progit-data:/data \
  localhost/progit:latest
docker run -d --name progit \
  -p 3000:3000 -p 3443:3443 -p 2222:2222 \
  -v progit-data:/data \
  progit/progit:latest

Step 2: Complete Setup Wizard

  1. Open your browser and navigate to http://localhost:3000.
  2. Fill in your desired Super Administrator username, email, and password.
  3. Click Complete Installation & Create Super Admin. ProGit will lock the setup and redirect you to the main dashboard.

Step 3: Create & Push to Your First Repository

# Create test directory and initialize git
mkdir my-project && cd my-project
git init
echo "# Hello ProGit" > README.md
git add README.md
git commit -m "Initial commit"

# Push over Smart HTTP
git remote add origin http://localhost:3000/<your-username>/my-project.git
git push -u origin main
SSH Support Out of the Box
You can also push over SSH at ssh://git@localhost:2222/<your-username>/my-project.git once you add your public key in User Settings > SSH Keys.

Getting Started / Architecture & Zero CGO

Architecture & Pure Go Engine

Understand how ProGit achieves maximum portability, concurrency, and security with zero CGO dependencies.

Pure Go SQLite WAL Engine

Traditional Git web applications that use SQLite rely on CGO bindings to the C SQLite library (such as mattn/go-sqlite3). This causes several critical operational headaches: slow cross-compilation, reliance on host GCC/Clang toolchains, and complex multi-architecture container setups.

ProGit completely eliminates CGO by using modernc.org/sqlite — a 100% pure Go translation of SQLite. Features include:

  • Zero CGO (CGO_ENABLED=0): Single static Go binary without libc/musl dependency conflicts.
  • Write-Ahead Logging (WAL) Mode: Allows concurrent readers without blocking write transactions.
  • Busy Timeout & Mutex Protections: Configured with 5000ms busy timeout to prevent database is locked errors during high-volume Git pushes.

Technology Stack

ComponentTechnologyPurpose
Backend EngineGo 1.24+ (Zero CGO)High concurrency HTTP, SSH, Git Smart Protocol
Databasemodernc.org/sqlite (WAL)Embedded, fast relational storage with zero external DBMS
Frontend UIReact 19 + Vite + TailwindGitHub-class SPA embedded directly in Go binary
Code HighlightingPrismJSOnline file view and Prettier syntax editing
Container RuntimePodman / Docker (Alpine 3.21)Compact ~37 MB production image

Installation / Podman & Docker

Podman & Docker Deployment

Deploying ProGit with production-grade container isolation and persistent volumes.

Automated Deployment Script

ProGit includes dedicated scripts for one-click building and deployment using Podman or Docker:

# Build the lightweight Alpine container image (~37 MB)
bash podman/build.sh

# Deploy with persistent volumes and healthcheck validation
bash podman/deploy.sh

Volume Persistence

ProGit stores all state in /data inside the container. We recommend mapping named volumes to ensure seamless data persistence across container updates:

Internal PathVolume Purpose
/data/dbSQLite database file (progit.db) and WAL journal
/data/repositoriesBare Git repositories (.git)
/data/configCustom app.ini configuration overrides and SSL certs
/data/sshHost SSH keys for built-in port 2222 server

    image: localhost/progit:latest

Installation / Standalone Binary

Standalone Binary Installation

Run ProGit directly on Linux or macOS as a native system daemon without containers.

1. Create System User and Directories

sudo adduser --system --shell /bin/bash --gecos 'ProGit Version Control' --group --disabled-password --home /home/git git
sudo mkdir -p /data/db /data/repositories /data/config /data/logs
sudo chown -R git:git /data

2. Place Binary

sudo cp progit /usr/local/bin/progit
sudo chmod +x /usr/local/bin/progit

3. Systemd Service File

Create /etc/systemd/system/progit.service:

[Unit]
Description=ProGit Service
After=syslog.target
After=network.target

[Service]
Type=simple
User=git
Group=git
WorkingDirectory=/data
ExecStart=/usr/local/bin/progit web
Restart=always
Environment=PROGIT_APP_NAME="ProGit"

[Install]
WantedBy=multi-user.target

Enable and start the service:

sudo systemctl daemon-reload
sudo systemctl enable --now progit

Installation / HTTPS & TLS

HTTPS & TLS Configuration

Securing Git traffic with automatic TLS, HSTS, and custom certificates.

Built-in HTTPS Server

ProGit features a native HTTPS engine that runs simultaneously alongside HTTP. To activate TLS directly in conf/app.ini:

[server]
PROTOCOL = https
DOMAIN = git.example.com
ROOT_URL = https://git.example.com:3443/
HTTP_PORT = 3000
HTTPS_PORT = 3443
CERT_FILE = /data/config/https/cert.pem
KEY_FILE = /data/config/https/key.pem

Automatic Self-Signed Certificates

If CERT_FILE or KEY_FILE are not specified when PROTOCOL = https, ProGit automatically generates an ECDSA P-256 self-signed certificate on boot, ensuring immediate encryption without configuration.

Installation / Reverse Proxy

Reverse Proxy Setup

Configuring Nginx or Caddy in front of ProGit for SSL termination and custom domains.

Nginx Configuration

server {
    listen 80;
    server_name git.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name git.example.com;

    ssl_certificate /etc/letsencrypt/live/git.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/git.example.com/privkey.pem;

    client_max_body_size 500M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Caddy Configuration

git.example.com {
    reverse_proxy 127.0.0.1:3000
    request_body {
        max_size 500MB
    }
}

Configuration / Database & SQLite WAL

Database & SQLite WAL Mode

How ProGit configures SQLite for high-concurrency enterprise workloads.

Write-Ahead Logging (WAL)

ProGit automatically configures SQLite with the following pragmas on connection initialization:

PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;
PRAGMA foreign_keys = ON;

Automated WAL Checkpoints

In WAL mode, writes are committed to a temporary journal file (progit.db-wal) and periodically merged into the main database file. Administrators can trigger a manual checkpoint at any time via the admin endpoint:

curl -X POST http://localhost:3000/api/v1/admin/maintenance/wal-checkpoint \
  -H "Authorization: Bearer <admin_token>"

Configuration / SSH Server

Built-in SSH Server (Port 2222)

Secure, key-based Git operations without needing host OpenSSH integration.

SSH Key Generation

ProGit generates host Ed25519 and RSA keys in /data/ssh/ if none exist. Git clients can authenticate directly using their public keys.

User Key Registration

  1. Generate an Ed25519 key pair on your local machine: 
    ssh-keygen -t ed25519 -C "your_email@example.com"
  2. Copy the contents of ~/.ssh/id_ed25519.pub.
  3. In ProGit, navigate to User Settings > SSH Keys > Add Key.
  4. Paste the public key and save. You can now clone and push over SSH!

Repository Forking

Fork repositories into your personal account or any organization you administer.

Fork Mechanics

When you click Fork on any repository:

Operations & FAQ / Backup & Recovery

Backup & Disaster Recovery

Simple, reliable procedures to backup and restore ProGit data.

Backup Procedure

Because ProGit uses SQLite and local bare Git repositories, backup requires capturing only two directories:

# 1. Trigger SQLite WAL Checkpoint
curl -X POST http://localhost:3000/api/v1/admin/maintenance/wal-checkpoint -H "Authorization: Bearer <token>"

# 2. Archive data directory
tar -czvf progit-backup-$(date +%F).tar.gz /data/db /data/repositories /data/config

Restoring Data

# Extract archive to /data
tar -xzvf progit-backup-2026-11-01.tar.gz -C /

Troubleshooting & FAQ

Answers to common operational questions and error resolutions.

Q: Why do Git pushes over HTTP fail with 401 Unauthorized?

Ensure you authenticate with a valid username and password, or use a Personal Access Token (PAT) created from Settings > Access Tokens.

Q: How do I change the default SSH port from 2222?

Set SSH_PORT = <port> and SSH_LISTEN_PORT = <port> under [server] in app.ini, or pass PROGIT_SSH_PORT=<port> as an environment variable.

Q: How does ProGit Pages resolve file MIME types?

ProGit has a built-in MIME-type registry covering HTML, CSS, JavaScript, SVG, PNG, WebP, JSON, and WebAssembly. It delivers assets with proper Content-Type headers.
